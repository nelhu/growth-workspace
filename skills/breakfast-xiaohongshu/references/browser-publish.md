# Chrome 图文发布流程

在 Tiny.C 早餐生成后的默认发布阶段，或用户要求发布已有内容包时，读取并执行本流程。用户于 2026-09-14 明确授权每次生成后发布，包含每日自动化；先完成生成校验及内容包推送，再发布目标帖子。用户当次明确“仅生成”“不发布”或“预览”时不发布；仅修改 Skill 不触发历史补发。授权不包含其他账号、其他内容、修改旧帖或发布评论。可完成最后提交，无须在每个常规步骤重复询问；登录、验证码、账号限制及结果未知时仍按下文暂停与去重规则处理。

## 已验证经验与适用边界

- 每次发布新起独立 Chrome 进程，使用专用 `user-data-dir`，不得连接、抢占或关闭用户当前 Chrome。专用 profile 可保留 Tiny.C 登录态，但同一时刻只允许一个该 profile 进程。入口为 `https://creator.xiaohongshu.com/publish/publish`，选择当前可见的“上传图文”。不使用 `xiaohongshu-mcp`、`publish_content` 或 `breakfast_xhs.py publish`。
- 不固定指定 CDP 或 Computer Use。稳定、可见、唯一且语义明确的 DOM 控件使用 CDP，适合文件上传、文本写入、精确元素点击和结构化回读；Shadow DOM、画布、动态浮层、隐藏副本难以排除或 DOM 与视觉状态不一致时使用 Computer Use/实时截图。一个步骤可以用 Computer Use 定位并点击、再用 CDP 回读验证，或由 CDP 点击后用截图确认。最终以页面可见状态和编辑器原生实体为准，不以某个工具返回“Clicked”或“Typed”为成功证据。
- 本会话中，逐张上传、输入标题正文、提交后检查“发布成功”页面的流程已成功使用。成功页路径是 `/publish/success`；动态查询参数不是固定定位条件。
- 中文逐字输入曾出现缺字，优先对可编辑文本字段使用当前工具支持的 `setValue`。`paste` 曾出现旧剪贴板内容，不能把粘贴调用成功当作正文正确：每次读回全文，发现错贴即清除该字段并重新输入。
- 正文曾通过先写完整文本、再从后向前定位段首并插入换行完成排版。当前编辑器若正确保留多行文本，可直接输入，但仍须读回验证。
- 之前没有完成置顶评论发布；不得把正文提交成功描述为置顶评论已发布。话题出现 `#文本` 也不证明已绑定为平台话题。本次已验证 8 个候选通过真实点击成为原生话题，另 2 个只有“新建话题”而被删除；最终少于 10 个话题可以发布。
- 下列等待、分段及重试参数是用于可靠性的新默认值，不是已证明能够避免风控的参数。不得承诺“不被识别人机”，不使用随机点击、伪造人工行为、指纹伪装或其他规避平台检测措施。

## 独立 Chrome 进程

发布开始前先确认用户当前 Chrome 的 PID，随后启动专用进程并再次核对 PID；后续所有浏览器操作只连接专用 profile 的调试端口和 target。一个已验证的启动方式是：

```bash
open -na 'Google Chrome' -g --args \
  --user-data-dir='/Users/xuezi/Library/Application Support/Codex-Breakfast-Chrome' \
  --remote-debugging-port=0 \
  --no-first-run \
  --no-default-browser-check \
  'https://creator.xiaohongshu.com/publish/publish'
```

- 调试端口从专用 profile 的 `DevToolsActivePort` 实时读取，端口、PID 和 target ID 都不能写死。
- 连接前确认 `DevToolsActivePort` 存在且其路径属于专用 profile；缺失时停止，不能回退连接默认 Chrome。
- 每次发布任务都重新启动该专用 Chrome。若专用 profile 有遗留进程，先识别并只结束该专用进程，再启动新进程；不得结束用户主 Chrome。
- 同一页面复用一个持久 CDP 连接，不因页面跳转反复创建会话。CDP 客户端必须使用带可用 WebSocket 实现的运行时；本机已验证 Node 22 可用，Node 20 若缺少全局 WebSocket 不应继续硬跑。
- 新 profile 未登录时由用户完成登录或验证码。登录成功后回读页面账号，确认是 Tiny.C 再继续。

## 浏览器可靠性与平台合规策略

目标是减少动态页面、网络延迟和编辑器识别造成的误操作，不是伪装真人或绕过平台风控。实现依据采用浏览器自动化的通用可靠性原则：优先使用面向用户的 role/label/text 定位；动作前确认目标唯一、可见、稳定、可接收事件、已启用，文本字段还需可编辑；用页面状态和回读断言决定是否继续。参考 [Playwright Auto-waiting](https://playwright.dev/docs/actionability)、[Playwright Locators](https://playwright.dev/docs/locators) 与 [Selenium Waiting Strategies](https://www.selenium.dev/documentation/webdriver/waits/)。

发布模式必须执行以下规则：

1. 每次动作都基于最新 AX/截图重新定位，优先 role、label、placeholder、可见文本等用户可感知属性；不用旧坐标、脆弱 DOM 层级或隐藏元素。截图被缩放时先换算到原始像素，再按 DPR 换算为 CSS 坐标；坐标只服务于当前截图。
2. 点击前在最多 15 秒内确认元素唯一、可见、稳定、未被遮挡且已启用；输入前额外确认可编辑。条件不满足时不强制点击。
3. 等待必须由可观察状态结束，例如缩略图数量增加、字段值回读一致、候选列表出现、话题转为原生实体或 URL 进入成功页。固定间隔只用于短轮询，不用长睡眠替代状态判断。
4. 标题和正文优先一次写入可验证字段；正文需要分段时按语义边界处理。只有话题候选必须依赖逐键触发时，才对当前单个话题使用约 40–80 ms/字符的顺序输入，并在候选出现后立即停止；这个节奏用于确保输入事件被编辑器处理，不用于拟人。
5. 页面发生上传、候选选择、弹层开关或路由变化后，以 0.5–1 秒间隔检查目标状态，默认最多等待 15 秒；话题候选可能先显示“无结果”再异步出现，最多观察约 45 秒并在结束前刷新截图/AX；单张图片上传最多等待 60 秒。状态满足立即继续，不额外随机等待。
6. 可逆动作仅在回读确认“未生效”后重试，最多 2 次，退避约 1 秒、3 秒；重试前刷新 AX/截图。字段已部分生效、结果不明或可能产生重复内容时停止自动重试。
7. 不移动鼠标制造轨迹，不点击无关区域，不随机改变打字速度，不修改浏览器指纹/User-Agent，不隐藏自动化特征，不处理验证码。遇到验证码、风险提示、账号限制或平台强制声明立即暂停并交给用户。
8. 最终“发布”每次授权只点击一次；点击前先写 `publication.json.status=unknown`，点击后仅通过成功页或笔记管理实际记录确认结果。

## 参数速查

| 项目 | 默认值与判断依据 |
| --- | --- |
| 动作可交互等待 | 最多 15 秒；唯一、可见、稳定、可接收事件、已启用，输入框还需可编辑 |
| 状态轮询 | 每 0.5–1 秒检查可观察状态；完成条件满足即继续，不靠固定长睡眠猜测完成 |
| 话题候选等待 | 最多约 45 秒；短暂“无结果”后刷新实时截图/AX，确认是否出现迟到候选 |
| 输入分段 | 正文较长时每段约 50–100 字，按语义边界拆分；不强制逐字模拟打字 |
| 话题顺序输入 | 仅在候选依赖逐键事件时使用约 40–80 ms/字符；每次只输入一个话题并等待精确候选 |
| 输入确认 | 每次字段写入或段落插入后读回，检查中文、标点、换行及有无重复 |
| 上传等待 | 每张图最多观察 60 秒，确认上传完成且缩略图可见后再继续 |
| 普通动作重试 | 仅对可逆且已确认未生效的动作最多重试 2 次；约 1 秒、3 秒退避，先更新 AX/截图 |
| 最终提交 | 每次授权执行只点击一次“发布”；超时、断网或未知返回不能自动再次提交 |

不要把等待超过一分钟的单次阻塞调用作为轮询。遇到验证码、风险提示、账号限制或人机验证，立即暂停并交给用户处理；不代做验证码，不调整模拟参数尝试绕过。

## 发布前核验与重复提交保护

1. 明确目标日期、内容包及账号。读取目标目录的 `README.md`、`content-package.json` 和已有 `publication.json`，运行 `validate-manifest`；失败先修复，不能边发布边补齐。
2. 如已有 `publication.json.status=published`，不得重复提交。若为 `unknown`，先只读检查创作中心笔记管理；以标题、封面、时间等核对是否已创建。仍无法确定则暂停，不能把再次运行视为重试发布的授权。
3. 核对至少 3 张 `853×1280 px` 图片及顺序：家庭餐桌首图、总览信息图、菜品过程图。标题不超过 20 字符，使用当前早餐吸引力标题规则，不擅自恢复天数或栏目名前缀。
4. 正文不添加“配图为 AI 辅助搭配示意”等声明。按内容包准备正文、互动问题、明天预告和台账话题；置顶评论另行处理。核对话题与当日台账一致，不在编辑器中临时换为猜测的热词。台账可以有 10 个候选，发布页最终只保留能选择为已有原生话题的项目。
5. 浏览器只操作目标账号和目标笔记，不修改其他打开的页面。若已有发布草稿，不覆盖不明草稿；先核对是否属于本次内容包。

## 网页操作

每个动作批次后获取新的 AX 状态或截图，再决定下一步。元素编号及坐标只使用当前状态，不复用旧会话坐标；缺少 AX 元素时再依据当前截图点击。

1. 打开入口并选择当前可见的“上传图文”。页面可能保留负坐标或隐藏的同名 Tab，必须过滤不可见节点，不能按文本直接选择第一个。未登录则让用户完成需要其交互的登录；不搜索或导出账号凭据。
2. **逐张上传**：首图可精确定位 `input.upload-input[type=file]`；进入编辑器后，追加图片通常使用 `input[type=file][multiple]`，旁边可能存在单图替换或附件字段，不能笼统选择任意 file input。可以用 CDP `DOM.setFileInputFiles` 对真实字段上传；每张上传后等待完成，并从页面“图片编辑 N/18”等状态回读数量和顺序，避免重复图。若改用系统文件选择器，则用 `Command+Shift+G` 进入目标绝对路径并确认文件名。
   - 编辑器首次出现功能引导时，确认 `button.feature-guide__btn` 的可见文本为“我知道了”后关闭，再继续操作。
3. **标题**：写入内容包标题并读回，检查平台字数反馈。若平台限制与本地计数不同，先调整为等义短标题并在交付记录中保留最终使用的标题。
4. **正文**：标题字段可用 `input[placeholder="填写标题会有更多赞哦"]` 定位，正文可用 `.tiptap.ProseMirror[contenteditable=true]` 定位。依次写正文、互动问题、明天预告，段落间保留空行。DOM click 返回成功不代表 contenteditable 已获焦点；输入前确认 `document.activeElement`，输入后全文回读。优先 `setValue`，不可用时采用可读回的方法；不要把剪贴板内容未经核对直接提交。需逐段修复换行时，从后向前定位段首再插入换行，避免前面编辑改变后续位置。开始绑定原生话题后禁止整体重写正文，以免实体丢失。
5. **话题逐个绑定（硬规则）**：按台账顺序，每次只处理一个话题，完成下列闭环后才输入下一个；禁止一次粘贴整组话题，也不能用 `setValue` 重写整个正文来追加话题，更不能直接构造或注入 `data-topic`。
   - 将光标放到正文末尾的话题区域，输入当前单个 `#话题名`，或通过“话题”按钮输入该名称。
   - 等待 `[role=tooltip]` 中当前话题的候选/识别反馈。出现候选列表时，通过 CDP 元素点击或 Computer Use/当前实时截图坐标点击名称完全匹配的现有候选；根据候选 DOM 是否稳定可读动态选择。必须触发页面真实点击，不得无条件按 Enter、点击首条、改选近似话题或点击“新建话题”。候选文本可能含零宽字符，匹配时先规范化不可见字符再比较完整名称。
   - 短暂出现“无结果”时继续有界轮询并重新截屏，不能立即判定不存在。本次实测候选可能延迟出现。到等待上限仍无现有精确候选，或页面只提供“新建话题”时，删除刚输入的普通文本，记录为 `omitted`，继续下一个话题；允许最终少于 10 个。
   - 点击后获取新的 AX/截图，确认刚输入的名称已转为编辑器原生话题样式（用户样例中的蓝色话题文本），并轮询 `.tiptap .tiptap-topic` 最多 15 秒。点击后第一次 DOM 回读可能尚未更新，不能立即再次点击，否则可能重复添加。
   - 原生实体从 `.tiptap .tiptap-topic[contenteditable=false][data-topic]` 读取，名称以 `data-topic.name` 为准；不要用全局 `.tiptap-topic` 计数，因为预览区可能复制同一实体，也不要用 `textContent`，其中可能混入隐藏的 `[话题]#` 文本。
   - 确认当前话题完整且未重复，前面已绑定的话题仍保留，然后退出当前话题输入状态、移到其后，再添加下一个。不要提前批量输入后统一检查。
   - 最后按台账逐项核对所有候选的状态，以及最终保留实体的名称、数量和顺序，保存最终截图/AX证据。`omitted` 项不得残留为普通 `#文字`；任一项目状态不明时记录 `unknown` 并暂停发布，不擅自换词或带着未绑定话题提交。
6. **声明与其他设置**：按 Tiny.C 当前偏好，不主动选择“笔记含 AI 合成内容”或“含 AI 生成内容”。若平台自动添加或强制要求则保留并告知，不能移除强制标识或绕过要求；个人账号声明不是平台豁免证明。原创声明中的协议或承诺不能仅因内容包 `is_original=true` 而自动同意。无关定位等权限不主动开启。
7. **最后核对**：获取新 AX/截图，检查实际账号、图片数量与顺序、最终标题、完整正文、所有已识别话题、已删除的无结果项、可见范围及声明状态。发布按钮可能由 Web Component/Shadow DOM 承载，普通 `querySelectorAll("button")` 为空不代表按钮不存在；结合 AX、实时截图和 `elementFromPoint` 确认按钮可见且 `submit-disabled=false`、`submit-loading=false`。点击之前先写入 `publication.json`，标记 `status=unknown`、`submission_attempted_at` 为当前时间，说明“即将提交，结果待核实”；即使进程中断，下次也必须先查笔记管理。保存核验结果后，仅点击一次“发布”。
8. **结果核验**：点击后立即保存 AX、URL 和截图；成功页可能数秒后自动返回。看到明确“发布成功”并处于成功页，或在笔记管理找到本条对应笔记，才能写为 `published`。仅有按钮点击返回、页面跳转、加载结束或泛化提示不构成成功证据。提交后无明确结果则写 `unknown`，保存当前页面证据并停止重复提交；提交前被验证码、校验或账号问题拦截则写 `blocked`。

## 已验证 DOM 与状态定位

这些选择器用于提高定位效率，动作前仍需确认当前页面上的节点可见、唯一且语义一致：

| 目标 | 已验证定位或状态 | 注意事项 |
| --- | --- | --- |
| 上传图文 Tab | `.creator-tab` 的可见节点 | 页面存在负坐标隐藏副本，不能直接取第一个同名元素 |
| 首图上传 | `input.upload-input[type=file]` | 上传后等待进入编辑器 |
| 追加图片 | `input[type=file][multiple]` | 排除单图替换和普通附件字段 |
| 功能引导 | `button.feature-guide__btn`，文本“我知道了” | 仅在弹层可见时点击 |
| 标题 | `input[placeholder="填写标题会有更多赞哦"]` | 写入后全文回读，避免正文误入标题 |
| 正文 | `.tiptap.ProseMirror[contenteditable=true]` | 输入前确认焦点，话题绑定后禁止整体重写 |
| 话题候选 | `[role=tooltip] .name` | 只点击可见且规范化后完整名称相等的现有候选 |
| 已绑定话题 | `.tiptap .tiptap-topic[contenteditable=false][data-topic]` | 名称读取 `data-topic.name`，不能全局计数 |
| 图片完成数 | 页面可见“图片编辑 N/18” | 每张上传后确认 N 增加且顺序正确 |
| 发布按钮 | AX button“发布”及实时截图 | 可能位于 Web Component/Shadow DOM；同时检查 disabled/loading 状态 |
| 发布成功 | `/publish/success` 与明确“发布成功”文案 | 立即保存证据，页面可能自动返回 |

## 独立发布记录与交付同步

话题识别视觉参考：[用户提供的蓝色话题样例](../../../assets/xiaohongshu-topic-recognition.png)。它仅说明预期效果，不作为当前表单已绑定成功的证据；每次仍须现场逐个核验。

在当日内容目录中维护 `publication.json`。它用于记录网页发布事实，不是改变 `content-package.json` 生成策略的开关：保留生成包的 `status=ready_for_review`、`should_publish=false`，不要通过篡改这些字段绕过生成校验。

记录至少包含：

```json
{
  "date": "YYYY-MM-DD",
  "status": "published | unknown | blocked",
  "channel": "chrome_computer_use | chrome_cdp",
  "account": "页面实际核对的账号",
  "published_title": "实际使用的标题",
  "visibility": "页面实际核对的可见范围",
```
